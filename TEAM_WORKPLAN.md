## 2. Backend / Frontend Developers

### Main Responsibility

Build the functional web application and keep the implementation aligned with the agreed scope and design.

### Responsibilities

- Set up and maintain the frontend/backend codebase.
- Define the implementation architecture with the team leader.
- Build reusable responsive React components.
- Implement map discovery and service search.
- Implement service profile and community insight views.
- Implement forms, validation, and contribution flow.
- Build Express API endpoints and business logic.
- Design/implement the PostgreSQL schema.
- Implement aggregation, scoring, and confidence logic.
- Integrate frontend, backend, and database.
- Test their own work before handing it to QA.
- Fix high-priority bugs quickly.
- Keep desktop and mobile behavior aligned with the approved design.
- Share feasibility feedback with designers and researchers.

## 3. Research / Quality Assurance

### Main Responsibility

Strengthen the project's evidence and decisions while continuously testing whether the prototype works correctly and supports the intended problem.

### Research Responsibilities

- Research credible evidence for the problem SerbisYO addresses.
- Research comparable products and identify meaningful differences.
- Research SDG alignment and prepare evidence for the pitch.
- Research community-powered information systems, service transparency, accessibility, moderation, and reputation risks.
- Gather references that may help UI/UX and development decisions.
- Suggest scope improvements while respecting the sprint limit.
- Challenge unclear requirements before they become code.

### QA Responsibilities

- Prepare test cases while development is ongoing.
- Test completed features immediately.
- Test desktop and mobile layouts.
- Test navigation, search, forms, map interactions, filters, and calculations.
- Test invalid input, empty states, long content, loading states, and error handling.
- Verify scoring output using known sample data.
- Report bugs clearly with reproduction steps.
- Classify issues as Critical, Major, Minor, or Cosmetic.
- Retest fixes.

Priority order:

> **Critical -> Major -> Minor -> Cosmetic**

## 4. UI/UX Designer / Pitch Deck Designer

### Main Responsibility

Create a coherent, responsive, feasible design for the complete core experience, then translate the same visual direction into the pitch deck.

### Responsibilities

- Research relevant interface references.
- Build a mood/reference board.
- Establish color palette around the team leader's primary color.
- Define typography, spacing, surfaces, states, and component style.
- Wireframe the full core flow.
- Design desktop and mobile versions.
- Design reusable component states.
- Keep service intelligence easy to scan and understand.
- Coordinate designs with developers before polishing screens.
- Adjust designs when an interaction is not feasible in the sprint.
- Prepare pitch-deck visuals, diagrams, system flow, and mockups.
- Keep the pitch deck visually aligned with the final product.

## 5. Presenters

### Main Responsibility

Understand the product deeply enough to explain the problem, solution, technical direction, impact, and live demonstration clearly.

### Responsibilities

- Follow development progress from the start.
- Understand the problem and target users.
- Understand the complete core user flow.
- Understand the SerbisYO Score and confidence model.
- Understand the technology stack at a high level.
- Understand the SDG alignment.
- Prepare the presentation narrative and transitions.
- Coordinate who speaks during each section.
- Prepare for likely judge questions.
- Practice live demo timing and recovery if something fails.
- Ensure claims in the presentation match the actual prototype.

## 6. Team Leader Direction

The team leader supports all roles, especially development, but each role should first take ownership of its assigned work.

Team leader responsibilities:

- Protect the overall product direction.
- Maintain scope discipline.
- Resolve cross-role disagreements quickly.
- Help with development and technical decisions.
- Review UI/UX direction.
- Review research and QA output.
- Coordinate integration between roles.
- Track blockers and deadlines.
- Keep the pitch aligned with the actual system.
- Make final calls when the team cannot reach a timely decision.

Team expectation:

> **Try to solve tasks within your assigned role first. Ask for help when blocked, not only when the deadline is near.**

## 7. Collaboration Rules

- Roles are primary responsibilities, not strict walls.
- Everyone may suggest improvements to product, design, development, research, QA, and presentation.
- Major scope changes require team discussion/leader approval.
- Developers should give feasibility feedback early.
- Designers should share incomplete wireframes early instead of waiting for perfect screens.
- QA should test throughout development, not only at the end.
- Presenters should learn the system while it is being built.
- Blockers should be communicated immediately.
